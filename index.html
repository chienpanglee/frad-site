Why FRAD

Storage: your data, under your control

You want full control of your data, but it can be hard. FRAD is a storage platform that scales on demand, vertically with ZFS and horizontally with Ceph.

More
  • Up and down on one node. Disks join or leave the host pool one at a time, as stripe, mirror or raidz. A disk is evacuated before it is released, so shrinking is as easy as growing.
  • Out and in across nodes. One node grows into a Ceph cluster with no re-install. Replicas and failure domain follow the number of hosts, and a node leaves after its disks drain.
  • Block, file and object from the same cluster, on your own hardware. Each disk goes to ZFS or Ceph on its own, and can move between them.

Security: update safely, update fearlessly

CVEs emerge nonstop, release cycles and patch delivery are too slow, and updating is a pain. When upstream has a fix, FRAD can have it.

More
  • Three channels by risk. Base-OS security fixes, FRAD’s own code and a full image each travel on their own channel, so a CVE fix does not wait for a FRAD release.
  • An update you can undo. in progress If a node does not come back healthy after an update, it returns to the version it ran before, by itself.
  • Signed releases. Every release is signed, and air-gapped sites update from the same bundle.

Quick deployment and scaling

Everything should take a few minutes: installation, configuration, joining a cluster, decommissioning, upgrades.

More
  • One image, every medium. ISO, USB stick, PXE or UEFI HTTP boot install the same system.
  • One screen at first boot. FRAD proposes a complete configuration, finds a cluster on the network, and applies it with one key, or runs unattended for a fleet.
  • Join and leave in place. A new node joins the cluster it finds, and a node leaves after its disks drain, with no re-install of the rest.
  • Try it first. A FRAD node runs on your own machine from a browser, before you download anything: ask for the booth.

Can change later

Not sure what to choose on the first configuration screen? No problem. Press a to accept and apply the defaults. It just works, and everything can be changed afterwards.

More
  • Defaults that work. The proposed setup is a production-shaped node, not a demo: mirrored boot pool, replication, firewall and certificates already on.
  • Every choice stays open. Hostname, addresses, the storage network, the control role and where each disk goes can all change on a running cluster.
  • No re-install. A rename or readdress updates Ceph, the cluster and every peer together.

Who needs FRAD

Three kinds of teams run into these problems most often. If you recognise yours, FRAD is worth a closer look.

Regional hosting providers and smaller cloud operators

You sell storage, or the services that run on it, without a large storage operations team behind it.

  • One product to run. Operating system, storage, clustering, high availability and the CLI install and update together.
  • Grow without re-architecting. Start with one node, add nodes as customers come, and retire them after their disks drain.
  • Patch without a project. Security fixes arrive on their own channel and roll through the cluster one node at a time.

A good fit if installing, patching and growing storage takes most of your team's time.

Server OEMs and infrastructure integrators

You ship hardware and want one storage software stack that goes onto every box the same way.

  • One image, every medium. ISO, USB, PXE or UEFI HTTP boot install the same system, attended or unattended for a fleet.
  • Supportable in the field. Every release is signed, and sites without internet update from the same bundle.
  • Easy to demo. Your customers can try a FRAD node in a browser before any hardware arrives.

A good fit if you build storage appliances or turnkey racks and would rather not maintain your own OS.

Enterprises with on-premises or sovereign requirements

Your data has to stay on hardware you own, in a place you choose.

  • Block, file and object from one cluster on your own hardware, from a single node upwards.
  • Air-gapped by design. Install and update offline from signed bundles; nothing has to call home.
  • No first-day lock-in. Names, addresses, networks and where each disk goes can all change later, without a re-install.

A good fit if a workload must stay on premises, and the storage it needs is hard to install, update or grow.
