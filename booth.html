Try it · a FRAD node on your own machine

One command. The release arrives here, in a container.

The booth is the release: a container holding the install image, with its signatures when the build was signed, and qemu to run it. Run it, and this page finds it: the files to download, an install you can watch, then the console of the node it made, the nodes you add, and the Ceph dashboard, all right here. Nothing leaves your machine.

What you get: the whole booth. Download the release, install a node, add nodes, open the Ceph dashboard.

You needCheckIf it is missing
Dockerdocker run --rm hello-worldInstall Docker Engine for your distribution.
KVMls -l /dev/kvmTurn on virtualization (Intel VT-x or AMD-V) in the firmware setup. Inside a VM, turn on nested virtualization on its host.
Memoryfree -g6 GB free for the install and h1, 4 GB more for each node you add. With less, the booth still serves the downloads.

Run: paste the line in the box below into a terminal.

What you get: the downloads (the install image and its checksums). Installing and running nodes needs KVM, which macOS does not have: try those on a Linux or Windows machine, or watch the replays.

You needCheckIf it is missing
Docker Desktopdocker versionInstall Docker Desktop for Mac. On Apple Silicon the booth runs under emulation, so it takes longer to start.

Run: paste the line in the box below into Terminal. It leaves out the KVM and network devices, which Docker on macOS refuses.

What you get: the whole booth when WSL2 has KVM, otherwise the downloads. Windows is not tested yet: tell me how it goes.

You needCheckIf it is missing
Windows 11 with WSL2wsl --status in PowerShellwsl --install in PowerShell as administrator, then restart (Microsoft's guide).
Docker in WSL2docker version in the WSL2 shellDocker Engine inside the WSL2 distribution, or Docker Desktop with its WSL2 backend.
KVM in WSL2ls -l /dev/kvm in the WSL2 shellIn %UserProfile%\.wslconfig, under [wsl2], set nestedVirtualization=true, then wsl --shutdown and open the shell again. The CPU must support it. No KVM: use the downloads-only line.
Memoryfree -g in the WSL2 shellWSL2 gets half of the RAM by default: raise memory= in .wslconfig for 6 GB free, plus 4 GB for each node.

Run: paste the line in the box below into the WSL2 shell (for example Ubuntu), not PowerShell.

The moment the booth answers, this page shows its downloads and the box below offers the install. The image is about 2.4 GB, and the line pulls the current one each time. Install via CDROM or via USB runs unattended in the console for a few minutes, and the node that boots from it is h1.
